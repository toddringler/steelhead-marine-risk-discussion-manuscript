# Coordinator agent checklist

Manage an owner-assigned census task through sequential workers; do not author findings, substitute for independent review or integrate instead of the steward. Read repository `AGENTS.md`, [workflow](../workflow.md), [requirements](Steelhead_Organization_Census_Requirements.md), [format reference](../methods/staging-record-format.md) and role checklists. The workflow is authoritative for shared procedures.

1. **Preflight:** Confirm assignment type, permanent IDs, questions, coverage criteria, base/working state, time budget and permissions under workflow §1. Check live staging and worker status; never overwrite occupied/unknown work. Use configured model/effort intent and record actual settings or unknowns.
2. **Journal before dispatch:** Record worker ID/context, dispatch time, assignment/revision, expected output and next action in the ignored coordinator journal. While a worker executes, only wait/receive status/report progress—no concurrent census work.
3. **Researcher gate:** Wait for actual completion/stop. Validate addressed handoff, assignment/IDs, required source files/capture exceptions, exact proposals/hashes, deliverable coverage and preview. A missing field/render failure goes back for bounded repair, not invented coordinator content.
4. **Fresh reviewer:** Launch every reviewer pass in a fresh file-only session, with applicable written context/history and no researcher chat/private reasoning. Wait for stop, then validate exact current review hashes, scope and addressed transfer.
5. **Corrections:** Route bounded requests to researcher and revised proposals to a fresh reviewer. Preserve previous review and unchanged accepted work. Enforce workflow's correction limit; obtain explicit deferral/escalation rather than endlessly retry or change dispositions yourself.
6. **Steward:** Dispatch only after a valid reviewer handoff. Require dependency-complete eligibility, usable preview, exact approval basis/inventory, actual original-file retention and durable review/decision records. Standing approval does not grant commit or cleanup authority.
7. **Verify completion:** After steward stop, check retained inventory/hashes against the plan and report actual integrated/held IDs, coverage, evidence exceptions, corrections, validation, file/HTML links and Git/staging state. Stop; another organization needs an assignment.

Apply owner steering before each dispatch. Hold affected work if a decision is forthcoming, a consequential question remains, or worker state is uncertain. Follow workflow §§5 and 10 for pause/recovery; sending a task is not completion. Missing orchestration tools must be reported, not simulated. Do not create user-owned chats unless requested or contact other chats/services beyond authorized scope.

For a routing smoke test, use an explicitly synthetic fixture under `output/coordinator-smoke/`, not live staging or retained evidence. Test detection → correction → fresh review → mock steward integration, with completion/handoff/hash gates; record outcome/limitations in development output. A synthetic routing pass does not prove scientific quality or production recovery.
